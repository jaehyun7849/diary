# 한걸음 · 플랜두씨 운동 다이어리

헬스·걷기를 시작하려는 사용자를 위한 과제 6 웹앱입니다. 계획, 할 일, 실행 기록, 돌아보기를 Cloudflare D1 서버 데이터베이스에 저장합니다.

## 처음 사용하기

1. 첫 화면에서 **첫 운동 계획 만들기**를 누릅니다.
2. 기간·성공 기준·예상 시간을 실제 목표에 맞게 수정하고 저장합니다. 걷기 3회·헬스 2회 할 일 초안을 함께 만들 수 있습니다.
3. 실제 운동 후 **운동 기록**에 서울 기준 시작·종료 시각, 실제 운동 시간, 내용과 막힌 이유를 적습니다. 할 일을 마쳤으면 완료도 체크합니다.
4. 돌아보기 숫자를 눌러 근거 기록을 확인하고, 개선점 한 줄을 작성해 다음 계획으로 넘깁니다.

**실제 운동 기록은 자동 생성하지 않습니다.** 아직 운동을 시작하지 않았으므로 계획·할 일은 초안으로 준비되며 본인이 저장해야 합니다. 제출 전 본인 계획 1개, 할 일 5개, 실제 실행 기록 3개 이상과 돌아보기를 채워야 합니다.

## 과제 구현 범위

- T06-C04~08: 계획 기간·우선순위·성공 기준·예상 시간, 수정 전 전체 스냅샷과 고정 계획 ID.
- T06-C09~20: 할 일 생성·수정·완료·취소·삭제, 마감일·우선순위·태그·예상 시간, 검색·필터·정렬. 동률은 생성 시각과 ID로 정렬.
- T06-C21~27: 실행 기록과 계획 분리, 서울 시각 입력→UTC 저장, 실시간 분 단위 기록, 완료 테이블의 task_id 기본키로 중복 방지. 완료·취소는 원자적 DB 배치.
- T06-C28~33, C83: 삭제하지 않은 할 일을 마감일 기간으로 집계. 완료·미완료 지연·막힘 고유 할 일 수, 예상/실제 합계와 차이, 숫자에서 기록 조회, 개선점→다음 계획.
- T06-C34~36: D1 저장·새로고침 복원, 수정 이력과 삭제 자료를 포함한 전체 JSON 내보내기.
- T06-C57~60, C82: React 텍스트 이스케이프, SQL 매개변수 바인딩, 비밀키 없는 서버 DB 바인딩, 첫 화면 공개 안내, 제출 안내 페이지.
- T06-C01: 공개 배포 후 앱과 `/source`를 시크릿 창에서 확인합니다.
- C78~81은 본인이 실제로 사용해서 충족해야 합니다.

## 짧은 확인 방법 4줄

1. 어디로 가나요: 배포된 앱 첫 화면에 접속합니다.
2. 무엇을 하나요: ① 계획 저장·수정 ② 할 일에 실제 운동 기록 입력 ③ 돌아보기 숫자를 눌러 근거를 확인합니다.
3. 무엇이 보이면 통과인가요: 원래 계획이 수정 이력에 남고 실제 기록과 정확한 통계가 연결되며 새로고침 후 같은 값이 보입니다.
4. 안 될 때 무엇이 보이나요: 오류 안내가 나타나고 입력 내용은 유지됩니다. 연결을 확인하고 다시 저장합니다.

## AI와 내 판단 3줄 — 본인이 검토할 초안

1. AI에게 맡긴 일: 웹 화면·API·DB·집계 구현과 검증.
2. 내가 직접 판단한 일: 운동을 주제로 선택하고 헬스·걷기를 관리하기로 정했습니다. 세부 일정과 시간은 사용 전에 직접 확인합니다.
3. AI 제안을 따르지 않은 일: 아직 확인된 사례가 없습니다. 실제 사용 중 거절하거나 고친 제안이 생기면 그 이유를 적습니다.

## 개발

Node.js 22.13 이상. `npm run install:ci`, `npm run db:generate`, `npm run build` 순서로 준비합니다. 빌드 후 `node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_nosy_stick.sql`로 최초 로컬 DB를 만듭니다. 이미 적용한 마이그레이션은 반복 실행하지 않습니다. `npm run dev`로 로컬 미리보기를 시작합니다.

소스 공개용 JSON은 `node scripts/export-source.mjs`로 갱신합니다. 통계 검증은 `node --test tests/metrics.test.mjs`, 타입 검사는 `npx tsc --noEmit`입니다. 로컬과 배포 DB는 별개이며 로컬 테스트 기록은 배포되지 않습니다.

DB 명세: `contracts/pds-schema-v2.json`. 서버 저장 실패 시 성공으로 표시하지 않으며 화면의 입력을 유지합니다. 전체 데이터 내보내기는 현재 서버에서 불러온 자료를 단일 JSON으로 저장합니다. 데이터 가져오기 기능은 이번 과제 범위에 포함하지 않았습니다.
